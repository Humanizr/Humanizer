import coverage from './language-coverage.json';

export const localeProfileRoots =
  coverage.locales?.map(({locale}) => locale) ?? coverage.cultures ?? [];
export const acceptedCultureInventory = coverage.acceptedCultureInventory;
export const acceptedCultures = acceptedCultureInventory?.mappings ?? [];

# Supported cultures

Humanizer 4 ships {localeProfileRoots.length} generated locale profile roots
and accepts {acceptedCultures.length} exact `CultureInfo` names. An accepted
regional name can reuse a same-language profile root. Use
`Configurator.IsCultureSupported` to check a requested culture by exact name;
Humanizer does not infer support by walking an arbitrary .NET parent chain.
Calendar or numeric formatting uses .NET globalization data when a profile
does not need a Humanizer override.

## Example

Use a culture code from the list with `CultureInfo`:

```csharp
using System.Globalization;
using Humanizer;

var culture = CultureInfo.GetCultureInfo("pt-BR");
Console.WriteLine(123.ToWords(culture));
```

The output is:

```text
cento e vinte e três
```

## Locale profile roots

These {localeProfileRoots.length} codes own Humanizer's generated locale data.
They are not the complete list of exact culture names accepted by the public
registries.

<ul className="supportedCultureList" aria-label="Locale profile roots">
  {localeProfileRoots.map((locale) => (
    <li key={locale}><code>{locale}</code></li>
  ))}
</ul>

## Accepted culture names

This is the generated exact-name inventory used by
`Configurator.IsCultureSupported` and Humanizer's built-in registries. The
left code is the accepted `CultureInfo.Name`; the right code is the locale
profile that owns its Humanizer data.

<ul className="supportedCultureList" aria-label="Accepted culture names">
  {acceptedCultures.map(({name, localeProfileOwner}) => (
    <li key={name}>
      <code>{name}</code> → <code>{localeProfileOwner}</code>
    </li>
  ))}
</ul>

## When output is wrong

Incorrect output from a localized Humanizer surface backed by one of these
profiles is a bug. If output is wrong, use the correction path.

[Open the correction guide](../contributing/report-language-issue.mdx) or
[open a prefilled locale issue](https://github.com/Humanizr/Humanizer/issues/new?title=Locale%3A%20describe%20the%20language%20issue&body=Culture%3A%20%0AHumanizer%20version%3A%20%0AAPI%20call%3A%20%0AExpected%3A%20%0AActual%3A%20%0APlatform%2FTFM%3A%20).
